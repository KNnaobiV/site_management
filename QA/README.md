# Site Management QA Test Suite

This directory contains the comprehensive end-to-end QA test suite for the Site Management application, implemented using Python, Playwright, and pytest.

## Structure
- `tests/`: Contains all the test files, categorized by feature.
- `utils/`: Contains reusable helper functions, API wrappers, factories, and custom assertions.
- `conftest.py`: pytest configuration and fixtures (e.g. browser context, test users).
- `pytest.ini`: pytest configuration file.

## Setup

1. Create a virtual environment (if not already in one) and activate it:
   ```bash
   python -m venv venv
   # Windows
   venv\Scripts\activate
   # macOS/Linux
   source venv/bin/activate
   ```

2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

3. Install Playwright browsers:
   ```bash
   playwright install chromium
   ```

## Environment Variables

The tests require a running instance of the application (both frontend and backend). By default, they assume:
- **Frontend URL:** `http://localhost:5173` (or wherever your Vite dev server runs)
- **Backend API URL:** `http://localhost:8000` (for API data seeding)

You can override these using environment variables (see `conftest.py` for details if implemented):
- `BASE_URL` (default: `http://localhost:5173`)
- `API_URL` (default: `http://localhost:8000`)

## Test Users & Roles

The tests automatically provision unique users for each test run using API fixtures. The primary roles used are:
- `project_creator`
- `project_manager`
- `consultant`
- `foreman`
- `unrelated_user`

These are managed via `utils/factories.py` and provided as fixtures in `conftest.py`.

## Running the Tests

To run the entire suite:
```bash
pytest QA/tests
```

To run a specific group of tests (e.g., authentication):
```bash
pytest QA/tests/auth
```

To run tests with a specific marker (e.g., `@pytest.mark.projects`):
```bash
pytest QA/tests -m projects
```

### Debugging & Headed Mode

To watch the tests run in a visible browser window (headed mode):
```bash
pytest QA/tests --headed
```

To slow down test execution to see what's happening:
```bash
pytest QA/tests --headed --slowmo=500
```

To use Playwright's UI mode for step-by-step debugging:
```bash
pytest QA/tests --ui
```

## Artifacts (Screenshots & Traces)
The `pytest.ini` is configured to retain screenshots, videos, and traces **only on failure**. They will be placed in the `test-results/` directory generated by `pytest-playwright`.

## Known Assumptions
- Tests assume a clean database or at least that tests do not interfere with each other (achieved via unique data generation per test).
- Tests assume the backend server is running and accessible at `API_URL`.
- Some tests verify API responses and DB states directly via requests to ensure backend enforcement of rules beyond just UI behavior.
